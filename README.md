# War Robots 手机端自动化工具

> 目标：自动打开游戏、浏览奖励广告并领取任务礼包；自动进战斗打 1 分钟以上再退，
> 以"低战绩"方式逐步降低荣誉积分（= 游戏难度），避免越玩越难。

---

## 1. 环境与前置条件

| 项目 | 说明 |
|---|---|
| 手机 | 已实测 realme RMX3366（Android 12 / SDK 31） |
| 连接 | USB 数据线，手机端已开启「开发者选项 → USB 调试」并授权本机 |
| ADB | 已随项目内置于 `tools/platform-tools/adb.exe`（v37.0.1），无需另装驱动 |
| 屏幕 | 游戏为横屏 2400×1080，脚本会自动锁定横屏 |
| 游戏 | `com.pixonic.wwr`（War Robots v12.4.1），Unity 引擎 |
| Python | 使用 DSH 内置 Python 3，仅依赖 numpy + Pillow |

### 首次连接检查

```powershell
# 查看设备是否已授权（应显示 "device" 而不是 "unauthorized"）
.\tools\platform-tools\adb.exe devices -l
```

若显示 `unauthorized`：在手机屏幕上勾选「始终允许使用这台计算机进行调试」并点「允许」。

## 2. 图形界面（推荐使用方式）

**日常交互请用网页界面，不需要敲命令。**

```powershell
双击 web.bat
```

会自动启动本地服务并打开浏览器（默认 `http://127.0.0.1:8765/`）。
关闭那个黑窗口即停止服务。

页面上可以直接点击：

| 区块 | 按钮 |
|---|---|
| 常用操作 | 识别界面 / 回到机库 / 领取任务奖励 / 读取荣誉积分 / 分值趋势 / **打一局** |
| 广告·领资源 | 每日任务 / **供给中心抽奖** / 广告流程 / **完整日常** |
| 降难度 | **循环打局**（可设局数） |

页面还会实时显示：**手机画面**（3 秒刷新）、**运行日志**（彩色）、
**分值记录**（最新值 + 首末变化 + 柱状图）、**当前界面**状态徽章。

其他特性：
- 任务在后台跑，可随时关掉网页，重开仍能看到进度
- 同一时间只允许一个任务（设备独占）
- 点「停止」是**安全停止**：若正在对局中会延后到安全点，
  不会违反"1 分钟内不得退出"的规则

> 命令行方式仍然保留（`wr.bat` / `engine.py`），适合脚本化或调试。

## 3. 关键技术说明

War Robots 是 Unity 游戏，**不暴露 Android 无障碍树**（`uiautomator dump` 只能拿到空 FrameLayout），
因此本项目全部采用 **截图 + 视觉识别 + 坐标点击** 的自动化方式。

### 2.1 坐标系（已实测校准）

锁定横屏后（`user_rotation=1` + 关闭自动旋转），
**`input tap` 的坐标系与截图坐标系完全一致**（均为 2400×1080 逻辑坐标）。

> ⚠️ 踩坑记录：若设备处于竖屏状态，游戏只在 1080×2400 中间渲染一条横带，
> 且触摸坐标会被系统旋转，导致点击错位。所以必须先锁定横屏。

### 2.2 界面状态识别（`ui_state.py`）

实测标定的判别特征：

| 界面 | 判别依据（按判定优先级排列） |
|---|---|
| `ad` 广告 | Activity 含 AppLovin / adview / gms.ads / admob |
| `play_store` | 前台是 com.android.vending |
| `battle_result` 战斗结算 | 顶部红色横幅（战败/胜利） |
| `hangar` 机库 | 右上橙色「前往战斗」占比 > 0.45，中央亮度 > 330 |
| `lottery_ready` 供给中心可抽奖 | 底部中央紫色「获取供给」占比 > 0.15（实测 0.53） |
| `reward_popup` 奖励弹窗 | 底部中央大绿「确定」占比 > 0.45 且背景暗 |
| `daily_tasks` 每日任务 | 顶部 4 标签行暗青占比 > 0.40（实测 0.544，2 标签页仅 0.166） |
| `battle_modes` 战斗模式 | 底部中央橙色按钮占比 > 0.15 |
| `event_reward_track` 奖励轨道浮层 | 右上角纯蓝 X（>150 px） |
| `leave_warning` 放弃战斗警告 | y765~855 条带同时有大面积纯红+纯绿按钮 |
| `battle_prep` 战前部署/阵亡复活 | 下部机器人卡片区青灰占比 > 0.15 且无绿色按钮 |
| `black_market` 黑市 | **整屏深紫占比 > 0.35**（实测 0.66，其它界面 < 0.01） |
| `event_pass` 活动通行证 | 左侧紫金"活动通行证"大卡片占比 > 0.05 |
| `event_tasks` 活动任务 | 底部绿色「完成全部」/ 右侧实心绿「获取」/ 紫色观看视频 |
| `battle` 战斗中 | **左上亮绿血量条**（实测战斗 0.23，其它界面全 0）+ HUD ≥ 3 |
| `dialog` 对话框 | 中央暗 + 整体暗 |

> **血量条是区分"真正在战斗中"与各种菜单的决定性判据**：
> 实测所有菜单（机库/商店/任务/黑市/结算/模式页）的左上绿条占比都是 **0.000**，
> 只有真正上场后才会出现（0.227）。早期版本用"沙地/暖色"判断，
> 在商店页会误判，已修正。

## 4. 目标一：广告浏览 + 礼包领取

```powershell
python engine.py ads --rounds 6 --minutes 15
```

### 3.1 四个广告来源（全部实测可用）

| # | 来源 | 入口路径 | 按钮 | SDK | 次数限制 |
|---|---|---|---|---|---|
| 1 | **每日任务** | 机库右侧第 1 个（对勾）→ 顶部「每日」标签 → 向下滚动 | 紫色「新增进度」 | AppLovin | 约 4~5 个/天 |
| 2 | 活动任务 | 机库左侧「活动」→ 右侧「任务」 | 紫色「新增进度 / 观看视频」 | AppLovin | 随任务刷新 |
| 3 | 黑市 | 机库左侧第 3 个（礼盒） | 右下紫色「免费钥匙 X100」 | AdMob | 约 12 小时冷却 |
| 4 | **供给中心抽奖** | 机库左侧第 2 个（怪物图标，带倒计时） | 底部紫色「获取供给」 | AppLovin | 3 次/天，每次冷却约 5 分钟 |

**实测证据**：
- 黑市看广告后钥匙 **1054 → 1154（+100）**，随后按钮变为「11时56分」冷却
- 供给中心抽奖后 **Pt 218 → 243（+25）**，底部变为「任务距离推出还有：4分43秒」
- 每日任务看 3 次广告后进度 **1/5 → 2/5**，累计领奖 2 次

### 3.2 广告次数用尽后的「战斗补充」机制

按实测规则实现：**广告次数用完后，每进入一场战斗可补充 1 次广告**，
该补充次数本身也有上限，最终会到达「今日无法再读广告」的状态。

```powershell
# 广告用尽后自动进战斗补充，最多 2 场
wr.bat ads --rounds 6 --replenish 2
```

流程：

```
观看各来源广告 → 全部无入口
        ↓
进战斗（严格遵守 ≥70 秒规则，有机甲上场）
        ↓
退出 → 重新尝试广告入口
        ↓
仍有广告 → 继续观看；仍无 → 判定今日已用完并结束
```

日志会明确输出：
```
广告次数可能已用尽 → 进入战斗补充（第 1/2 场）
补充战斗后广告: 1 次
补充后仍无广告 → 判定今日广告已用完
```

### 3.3 供给中心抽奖（每天 3 次，含 5 分钟冷却）

```powershell
wr.bat lottery              # 抽到冷却结束或达 3 次（会自动等冷却）
wr.bat lottery --no-wait    # 只抽当前可用次数，不等冷却
wr.bat ads --lottery        # 在广告流程里顺带抽奖
```

实现要点：
底部提示有**三种形态**（实测，务必区分）：

| 形态 | 底部文字 | 含义 | 脚本行为 |
|---|---|---|---|
| 可抽 | 紫色「获取供给」按钮 | 有次数 | 点击 → 看广告 → 抽奖 |
| 冷却中 | 「任务距离推出还有：**4分53秒**」 | 距下次约 5 分钟 | 等约 420 秒后重试 |
| **今日用完** | 「**剩余时间：21时31分**」 | 3 次已用尽 | 不再等待，直接结束 |

实测同一天抽满 3 次的记录：

| 时刻 | Pt 变化 | 事后提示 |
|---|---|---|
| 13:49 | 218 → 243 (+25) | 「任务距离推出还有：4分43秒」 |
| 14:02 | 非 Pt 奖励 | 「任务距离推出还有：4分53秒」 |
| 14:22 | 243 → 268 (+25) + 钥匙 x2000 | 「剩余时间：21时31分」 |

- 抽奖后出现的「你的奖励」弹窗会自动点绿色「确定」收下
- 注意：两种"不可抽"形态版式几乎一样，靠画面难以可靠区分；
  务实做法是**最多等 420 秒**，仍不可抽即判定今日已用完

### 3.4 礼包领取

1. 进入任务页 → 优先点底部绿色「完成全部」（实心度 0.97，一次领完）
2. 没有「完成全部」时逐个点右侧绿色「获取」（实测 343×88）
3. 领取后可能弹出「活动奖励轨道」浮层 → 自动点右上蓝色 X 关闭
4. 全部领完后向上滚动查找更多任务

按钮定位使用 `task_ui.py` 的精确检测器（按实测尺寸/位置过滤），
避免误点「全部任务」这类导航按钮。

### 3.5 广告安全处理（`ad_handler.py`）—— 重点

已实测两种 SDK 的不同行为，分别处理：

| SDK | Activity | 关闭方式 | 说明 |
|---|---|---|---|
| AppLovin | `com.applovin.adview.AppLovinFullscreenActivity` | 动态检测角部按钮：右上 X → 左上 ▶Next → BACK 兜底 | 视频 → 落地页 → 退出调查 → 关闭 |
| AdMob | `com.google.android.gms.ads.AdActivity` | **只用 BACK 键** | 版式复杂、Install 按钮极大，乱点必误触 |

> 关键修正：AppLovin 左上角按钮的**位置随广告版式变化**
> （实测见过 (175,68)、(228,67)、(212,85)、(286,68) 等），
> 因此改为运行时动态检测亮区，不再用固定坐标。
> Next 连续 4 次无效 → 自动改用 BACK。

**安全规则（硬编码）**：

- 🔴 **黑名单**：屏幕中央 `(420,150)-(1980,1080)`（Install/立即游玩所在）
  与右下 Google Play 区 `(1600,780)-(2400,1080)`，**任何情况下都不点击**
- 🟢 **白名单**：仅角部检测到的亮区（右上 X / 左上 Next）
- 🟠 **误入 Google Play / 浏览器**：只按 `BACK` 返回，**绝不安装任何推荐内容**
- 🔁 **连续广告**：单一广告结束后若立刻出现下一个，自动继续（上限 6 个）

## 5. 目标二：参与游戏并停留 ≥ 70 秒

```powershell
python engine.py battle           # 单次
python engine.py loop --cycles 5  # 多轮（并自动记录荣誉积分变化）
```

### 4.1 硬性规则（依据用户要求实现）

> **进入战斗后 1 分钟内退出会被判罚扣分，进而抬高后续匹配难度。**

实现要点（`engine.py`）：

| 规则 | 实现 |
|---|---|
| 停留 ≥ 1 分钟 | `MIN_BATTLE_SECONDS = 70`（1:10，比 1:05 更保险） |
| 计时起点 | **首次看到部署界面即开始计时**（最保守口径） |
| 双保险 | `stay_in_battle` 返回后再校验一次，不足则继续 `sleep` |
| 阵亡不退出 | 阵亡/复活界面持续点机甲卡片**换机甲上场**，继续等待 |
| 必须上机甲 | `MIN_DEPLOY_COUNT = 1`，退出前若未上场会补一次部署 |
| 绝不提前退 | `go_home()` 检测到在战斗中时**直接返回 False**，不强行退出 |
| 战斗提前结束 | 若先出现结算页，仍在计时内**不点退出按钮**，等满 70 秒 |
| 状态抖动容错 | 判断"离开战斗"需连续 3 次确认，单次误判不会导致提前退出 |
| **放弃战斗警告** | 见下节，**强制选「留在战斗中」** |

### 4.2 「切勿放弃战斗」警告框 —— 关键防护

游戏中若尝试退出，会弹出：

```
⚠ 注意！
您仍有机器人幸存，切勿放弃战斗！可能会被罚分！
否则您将受到处罚，且少赚奖励。

[ 离开 ]（红）        [ 留在战斗中 ]（绿）
```

**脚本识别该对话框并强制点「留在战斗中」**（坐标 `(1563,809)`，实测）：

- 状态名：`leave_warning`
- 判据：y 765~855 条带上**同时存在大面积纯红（>20000 px）与纯绿（>20000 px）**
- 处理：`force_stay_in_battle()`，3 次重试，**永不点红色「离开」**
- 该对话框在"机甲阵亡待复活"时反复出现，脚本已实测连续拦截 2 次成功

> 实测日志：
> ```
> force_stay_in_battle: 检测到放弃战斗警告，点击「留在战斗中」
> force_stay_in_battle: 已留在战斗中（state=battle_prep）
> ```

### 4.3 战斗内随机操作

只使用「移动 / 开火 / 转视角」这三类安全操作，**不使用任何退出类按钮**：

| 操作 | 坐标区域 | 权重 |
|---|---|---|
| 虚拟摇杆拖动（移动） | 左下 `(280,660)` 起，±130px | 30 |
| 开火/技能点击 | 右下 `(2050,700)-(2300,1000)` | 28 |
| 转视角拖动 | `(1400,400)-(2100,800)` | 22 |

每种操作间随机间隔 0.25~0.9 秒，避免机械节奏。

## 6. 难度分值（荣誉积分）读取与验证

### 5.1 路径

机库右侧竖排第 4 个图标（奖杯）→「我的联赛」标签页。

实测界面（黄金联赛 II）：

```
黄金联赛 II
   🏆 1700 - 1899
   ████████████████░░░░  1768/1899
```

- 分值 **1768**，联赛区间 1700–1899，下一级 1900
- **分值越高 → 匹配难度越大**，策略目标是让它下降

### 5.2 读取实现（`rating_reader.py`）

无外部 OCR 依赖，采用**数字模板匹配**：

1. 裁剪进度条文字区 `(640,388)-(1520,448)`
2. 二值化（白字阈值 185）→ 按列投影切分字符
3. 斜杠识别：逐行重心"从右上到左下"的趋势判定
4. 数字与 `templates/digits/*.npy` 做**位移搜索 + 高斯模糊归一化**相关匹配
5. 每个数字保存多个变体模板（原图 / 4 向平移 / 2 种缩放），共 62 个文件

模板由 `bootstrap_digits.py` 从**人眼确认过的真实截图**自举生成
（1848/1899、1808/1899、1768/1899 三组样本，已覆盖数字 1,4,6,7,8,9）。

### 5.3 实测验证结果（策略有效性证明）

| 时间 | 荣誉积分 | 说明 |
|---|---|---|
| 12:49:39 | **1848** | 初始基线 |
| 12:49:39 | **1808** | 3 轮对局后（每局 ≥70s 退出、有上场机甲） |
| 12:54:36 | **1768** | 累计约 6 轮后 |

**结论：每轮稳定下降约 40 分，累计 −80 分 → 匹配难度持续降低，策略有效。**

> 之后的实测（13:00~13:36）又完成了 4 局，全部在战 71~91 秒后退出，
> 期间成功拦截 2 次「切勿放弃战斗」警告（均选择「留在战斗中」），
> 未出现提前退出情况。可继续用 `engine.py loop --cycles N` 累积降分。

### 5.4 命令

```powershell
python engine.py rating        # 读一次并记入历史
python engine.py history       # 打印历史趋势
python rating_report.py        # 生成带趋势图的报告 + logs/rating_report.md
```

历史保存在 `logs/rating_history.jsonl`。

## 8. 常用命令速查

$py = "C:\Users\admin\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"

### 建议的使用节奏

**A. 降低难度（主目标）**

```powershell
# 每天执行，连续几天观察分值下降
& $py engine.py loop --cycles 6
& $py rating_report.py
```

每次循环 = 进场上机甲 + 随机操作 + 停留 ≥70s + 退出 + 读分值。

**B. 每日领资源（广告 + 礼包 + 抽奖）**

```powershell
# 每天一次：把每日任务广告、活动任务、黑市、抽奖都走一遍
& $py engine.py all --replenish 2
```

广告次数用尽时脚本会自动进战斗补充（每场 +1 次），
补充也用尽后明确报告「今日广告已用完」并正常结束，不会死循环。

## 9. 已知限制与注意事项

1. **挑战弹窗**：游戏中「你收到了挑战」对话框对注入点击不响应（实测所有坐标映射均无效，
   仅返回键可关闭），脚本会等待其自动超时后继续，不会卡死。
2. **广告内容不可控**：广告主素材可能包含成人向内容（实测出现过）。脚本只负责跳过，
   如需完全避免，建议在游戏设置或帐号地区层面关闭个性化广告。
3. **战斗结束判定**：若对局在 70 秒内就结束（例如全队被速灭），脚本会选择继续等待到
   计时满才退出，以遵守 1 分钟规则。
4. **横屏锁定**：会修改手机 `accelerometer_rotation` / `user_rotation`。
   脚本退出后如需恢复自动旋转：`adb shell settings put system accelerometer_rotation 1`
5. **分值变化需要时间**：荣誉积分并非每局即时变动，需要多轮（建议 5~10 局）后
   用 `history` 命令观察趋势。
6. **网络偶发失败**：进战斗时若遇到网络问题，可能长时间停在加载/模式页导致
   `enter_battle` 超时；脚本会安全放弃（不进场就不产生退出判罚），下次重跑即可。
   若手机端手动做了操作，重新执行命令前建议先 `engine.py home` 回到机库。
7. **广告入口会同时受冷却与次数限制**：每日任务广告数量、黑市钥匙冷却（约 12h）、
   供给中心抽奖（3 次/天 + 5 分钟冷却）各自独立。脚本会自动切换来源，
   全部用尽时按需进入战斗补充，补充也有上限，最终会报告「今日广告已用完」。
