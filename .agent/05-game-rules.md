> 这部分比代码更重要：**规则错了，代码再对也没用。**

## 1. 1 分钟退出规则（用户明确强调）

- 进入战斗后 **1 分钟内退出 → 判罚扣分**
- 扣的是**荣誉积分/战绩分**，进而导致**等级下降、匹配难度上升**
- 角色阵亡后**只要不退出就不算违规**：可以观战，或换机甲继续待在战场
- **保险做法：1:05 之后退**（本项目用 **70 秒**）

### 为什么要这么做（用户的策略意图）

> 随着角色升级和游戏时长增长，对战难度会不停增加。
> 如果 1 分钟后退而不产生战绩，系统会判定降低你的等级分/经验分，
> **等级降下来后匹配的对手难度就会降低**。

也就是：**用"低战绩退出"主动降低难度**。

### 实现对应

| 规则 | 代码 |
|---|---|
| ≥70 秒 | `MIN_BATTLE_SECONDS = 70.0` |
| 计时起点 | 首次看到部署界面 |
| 双保险 | `stay_in_battle()` 后再校验 |
| 不提前退 | `go_home()` 遇 battle/battle_prep 直接返回 False |
| 抖动容错 | 判"已离开战斗"需连续 3 次确认 |
| 必须上机甲 | `MIN_DEPLOY_COUNT = 1` |

## 2. 荣誉积分（游戏难度分值）

### 位置

机库右侧**奖杯图标** `(2300,590)` → 「我的联赛」标签 `(1110,130)`

界面实测（黄金联赛 II）：
```
黄金联赛 II
  🏆 1700 - 1899
  ███████████░░░  1768/1899
```

- 分值越高 → 难度越大
- 联赛区间与下一级门槛都会显示（1700–1899，下一级 1900）

### 实测降分效果（策略有效性的证据）

| 时间 | 荣誉积分 | 说明 |
|---|---|---|
| 12:49 | **1848** | 基线 |
| 12:49 | **1808** | 3 局后（−40） |
| 12:54 | **1768** | 累计约 6 局（−80） |

**结论：每局稳定 −40 分左右。**
（之后又打了 4 局，在战 71~91 秒，未再逐次记录分值。）

### 读取实现

`rating_reader.py`：数字模板匹配（无 OCR 依赖）
- 文字区 `(640,388)-(1520,448)`
- 二值化阈值 185 → 按列投影切分 → 斜杠靠"逐行重心右→左偏移"判定
- 与 `templates/digits/*.npy`（62 个变体模板）做**位移搜索 + 高斯模糊**相关匹配

已覆盖数字：**1,4,6,7,8,9**（**缺 0,2,3,5** → 读到含这些数字的分值会失败，
需要时用 `bootstrap_digits.py` 补样本）

## 3. 广告系统

### 3.1 四个广告来源（全部实测）

| # | 来源 | 入口 | 按钮 | SDK | 限制 |
|---|---|---|---|---|---|
| 1 | **每日任务** | 机库右侧对勾 `(2096,331)` → 「每日」`(1412,136)` → **向下滚动** | 紫色「新增进度」 | AppLovin | 4~5 个/天 |
| 2 | 活动任务 | 机库左侧「活动」→ 右侧「任务」`(2296,385)` | 紫色「新增进度/观看视频」 | AppLovin | 随任务刷新 |
| 3 | 黑市 | 机库左侧第 3 个 `(185,600)` | 右下紫色「免费钥匙 X100」`(2184,847)` | **AdMob** | ~12h 冷却 |
| 4 | **供给中心** | 机库左侧第 2 个 `(163,459)` | 底部紫色「获取供给」`(1247,1013)` | AppLovin | 3 次/天 + 5min 冷却 |

### 3.2 实测收益证据

- 黑市：钥匙 **1054 → 1154（+100）**，随后按钮变「11时56分」冷却
- 供给中心：Pt **218 → 243（+25）**、再 **243 → 268（+25）**，底部变「4分53秒」
- 每日任务：看 3 次广告后进度 **1/5 → 2/5**，领奖 2 次（金币 +10 等）

### 3.3 广告次数用尽 → 进战斗补充（用户说明）

> 广告每天可点数量有限。达到上限后，**每进入战斗一次可以补充一次广告**。
> 这个补充行为**本身也有次数限制**。最终会到达"今日无法再读广告"的状态。

**代码实现**：`engine.py goal_ads(..., replenish=N)`
```
广告全无入口 → 进战斗（≥70s）→ 退出 → 重试广告
  ├─ 有广告 → 继续看
  └─ 仍无   → 判定"今日广告已用完"，正常结束
```

⚠️ **该补充分支只验证到"能进入战斗阶段"，未完整实测"补充后真的出现广告"**
（见 `08-todo.md`）。

### 3.4 供给中心抽奖机制（实测修正版）

**每天 3 次**，每次抽奖要先看 1 次广告。

底部提示的**三种形态**（这是关键，别搞混）：

| 形态 | 底部文字 | 含义 | 正确应对 |
|---|---|---|---|
| 可抽 | 紫色「获取供给」按钮（宽 613） | 有次数 | 点它 → 看广告 → 抽奖 |
| 冷却中 | 「任务距离推出还有：**4分53秒**」 | 距下一次可抽约 5 分钟 | 等 ~310~420 秒 |
| **今日用完** | 「**剩余时间：21时31分**」 | 今日 3 次已用尽，等次日重置 | **不要等**，直接结束 |

> ⚠️ 这两种不可抽形态**版式几乎一样**（都是底部居中两行文字），
> 靠画面无法可靠区分。务实做法：最多等 420 秒，仍不可抽就判定"今日已用完"。

**实测抽奖 3 次的记录（同一天）**：

| 时刻 | 结果 | Pt 变化 | 事后提示 |
|---|---|---|---|
| 13:49 | 抽 1 | 218 → 243 (+25) | 「任务距离推出还有：4分43秒」 |
| 14:02 | 抽 2 | （非 Pt 奖励） | 「任务距离推出还有：4分53秒」 |
| 14:22 | 抽 3 | 243 → 268 (+25)，另得钥匙 x2000 | 「剩余时间：21时31分」 |

**结论**：3 次抽完后才出现 `21时` 级倒计时；前两次之间只有 ~5 分钟冷却。

**未知**：不知道"3 次"是每日固定给 3 次，还是"广告次数+战斗补充"换算来的。
若发现某天只能抽 1~2 次，优先怀疑是**广告次数不够**（抽奖要消耗广告）。

### 3.5 抽奖 / 广告的消耗顺序（实测）

抽奖会消耗广告机会；广告次数用尽后抽奖按钮也会变成冷却/不可用。

## 5. 战斗中行为

### 阵亡后

- 出现战前部署/复活界面（底部青色机甲卡片）
- **必须点卡片上场**（否则整局没参与）
- 期间如果尝试退出会弹「切勿放弃战斗」警告

### 结算页

- 顶部红/蓝横幅（战败/胜利）
- 底部左「前往机库」`(209,1012)`、右「前往战斗」`(2206,1012)`
- 所有数据为 0 说明该局基本没参与（早期未部署机甲的后果）

## 3.6 第五个广告来源：升级加速（用户补充，已实测）

**位置**：机库**顶部中央**，紫色「-4时 钟减少」按钮（带时钟播放图标）。
旁边绿色「X时XX分 加速」是花资源加速，**不是广告**。

**机制**：看一次广告 → **当前升级剩余时间减少 4 小时**。

**实测证据**：

```
升级按钮实测 bbox (1251,160)-(1526,226)  中心 (1388,193)
第 1 次广告后：剩余 9时56分 → 1时51分
（当天共看了 2 次，累计 -8 小时，符合"每次 -4 小时"）
```

**SDK**：这个入口用的是 **ByteDance 穿山甲**
（`com.bytedance.sdk.openadsdk.activity.TTFullWebActivity`），
关闭要点右上角灰色圆形 X（约 `(2309,113)`）。

**代码**：`engine.upgrade_by_ads(max_ads=12)`
- 反复点击直到按钮消失（升级完成 / 广告次数用尽）
- 日志会累计"共看 N 次（合计减少约 N×4 小时）"

**在 `all` 流程里的位置**：放在最后（用户说明"如果其他任务已完成，这个也可以做"）。

## 3.7 第六个广告来源：特惠礼包（用户补充，已实测）

**入口**：机库**最左侧、最下面**的**购物车图标** `(157, 700)`（带倒计时）。

**页面**：标题「特惠」，左侧有 **1 / 2 / 3** 三个分栏，右侧 5 张礼包卡横排。

**分栏内容会变**（重要）：

| 分栏类型 | 外观 | 按钮 | 能否点 |
|---|---|---|---|
| **广告礼包** | 深青底 | 紫「观看」/ 绿「获取」 | ✅ 可自动化 |
| **限时折扣** | 橙色 % 背景、`JP¥80` | 真钱购买按钮 | ❌ **绝不能点** |

**卡片顺序解锁**，每张需要看 N 次广告（如 `0/3` = 3 次），
看完变绿「获取」→ 领取后弹「购买成功」→ 点「确定」→ 变「已结束」→ 下一张解锁。

**实测一次完整运行**（用户只要求前 3 张，微芯片/纪念币跳过）：

```
分栏1 = 付费折扣页 → 全程跳过
分栏2 卡2 钥匙币300   : 2 次广告 → 领取成功
分栏2 卡3 动力电池350 : 1 次广告 → 领取成功
分栏3 卡1             : 1 次广告 → 领取成功
分栏3 卡2             : 1 次广告 → 领取成功
分栏3 卡3             : 2 次广告 → 领取成功
合计：广告 7 次，领取 5 次
```

**广告用尽时**按钮显示「不可用」，此时可用 `replenish` 参数进战斗补充后重试。

**代码**：`engine.watch_deals_ads(cards=3, replenish=0)`
